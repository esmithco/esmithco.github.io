AWS Backend — The Plan

Give the gym app a real backend: save every workout, sync across devices, log in, and later graph the progress. Built serverless so idle costs ≈ $0 — and each box is an AWS service to learn.
The architecture
Static site (GitHub Pages) │ fetch() with a login token ▼ [ Cognito ] ← login / signup · passwords · JWT token │ (token checked here) ▼ [ API Gateway ] ─► [ Lambda ] ─► [ DynamoDB ] REST endpoints Python workout history POST /workouts functions (per user) GET /workouts
Cognitofree: 50k users/moLogin & signup. Never store passwords yourself — it hands the app a JWT token.
API Gatewayfree: 1M req/moYour REST URLs. Checks the token before letting a request through.
Lambdaalways free: 1M req/moThe Python code behind each endpoint. No server to run.
DynamoDBalways free: 25 GBNoSQL table of workouts. Key: pk = USER#id, sk = WORKOUT#date#exercise.
Roadmap — one service per phase
  • 0Account & safety — IAM user (not root), MFA, AWS CLI, and a Zero-spend budget alarm. ← start here
  • 1DynamoDB + Lambda — a Python function that writes/reads one workout. Teaches IAM roles.
  • 2API Gateway — put a URL in front of the Lambda; call it from the site. Teaches CORS.
  • 3Cognito — add login; API rejects requests without a valid token; Lambda reads userId from the token.
  • 4Wire the app — on save → POST; on load → GET history → render a progress chart.
  • 5Infra-as-code — rebuild it all with AWS CDK (Python), reproducibly.
  • 6Data science — analyze the data (Athena / a notebook): weekly volume, PRs, estimated 1RM.
Phase 0 — account & safety (do first)
  • 1Create the AWS account (needs a card; free tier + the alarm below keep it at $0).
  • 2IAM → enable MFA on root, then stop using root.
  • 3IAM → create user brayan with console access + AdministratorAccess + MFA. Use this daily.
  • 4Billing → Budgets → Zero spend budget template + your email. (The guardrail.)
  • 5Pick one region (e.g. us-east-1) and stay in it.
Phase 1 — DynamoDB + Lambda
  • 1DynamoDB → Create table gym-workouts · partition key pk (String) · sort key sk (String) · defaults.
  • 2Lambda → Create function gym-workout · Python 3.12. Then Configuration → Permissions → attach AmazonDynamoDBFullAccess to its role.
  • 3Paste the code below → Deploy.
  • 4Test tab → run the two events → check DynamoDB → Explore items.
import boto3 from boto3.dynamodb.conditions import Key table = boto3.resource("dynamodb").Table("gym-workouts") def lambda_handler(event, context): action = event.get("action", "save") user = event.get("user", "demo") if action == "save": item = { "pk": f"USER#{user}", "sk": f"WORKOUT#{event['date']}#{event['exercise']}", "weight": str(event.get("weight", "")), "reps": str(event.get("reps", "")), } table.put_item(Item=item) return {"ok": True, "saved": item["sk"]} if action == "history": r = table.query(KeyConditionExpression=Key("pk").eq(f"USER#{user}")) return {"ok": True, "items": r["Items"]}
# test event — save { "action": "save", "user": "brayan", "date": "2026-08-24", "exercise": "press-inclinado", "weight": 20, "reps": 10 } # test event — history { "action": "history", "user": "brayan" }
Free-tier safety — the Zero-spend budget alarm emails you at the first cent. Serverless = pay-per-use, so idle ≈ $0.
Never put AWS access keys in the GitHub repo. Lambda uses its IAM role (no keys); your laptop uses an AWS CLI profile. Lambda derives the user from the verified token, never from a value the client sends.
